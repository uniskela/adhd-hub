# ADHD Hub v0.10.1: quieter forge sync and reliable Linux installation

## Summary

Build on v0.10.0 with two fixes: unchanged Hub content produces zero repository commits, and Linux `curl .../install.sh | sh -s -- .` completes without child processes consuming or printing installer source. Real content changes continue syncing immediately and existing wiki batching remains in place.

## Task 1: Stop redundant forge commits

- Add change detection to the shared individual-file writer before any Contents API write. Compare remote UTF-8 content and, when content is unavailable, a supported Git blob SHA. Missing files remain eligible for creation; indeterminate comparisons return an error instead of blindly writing.
- Make batch change-detection failure fall back to sequential per-file checks rather than pushing everything.
- Stabilize `INDEX.md`: preserve the existing generated timestamp and file bytes when the rendered content differs only by that timestamp.
- Count only actual writes as `uploaded`, including scaffold and rename results. Return `{skipped: true, reason: "unchanged", path: ...}` for unchanged individual files. Preserve aggregate fields, add `unchanged_files`, and set aggregate `unchanged: true` only when no writes or errors occurred.
- Test GitHub and Gitea unchanged/changed/missing behavior, scaffold idempotency and URL changes, batch fallback/read failures, rename behavior, and index timestamp stability.

## Task 2: Isolate Linux installer stdin

- Add a shared command-launch helper to the generated POSIX installer. Give child tools `/dev/tty` as stdin when it can be opened, otherwise `/dev/null`, so the outer shell retains exclusive access to the `curl | sh` script pipe.
- Apply it to durable CLI execution, `uvx`, CLI install/refresh, bootstrap execution, and companion commands reached through the CLI. Preserve intentional nested download pipelines, prompt behavior, arguments, paths with spaces, dry-run behavior, and exit status under `set -e`.
- Add Linux `sh -s` integration tests with stub commands that attempt to read stdin and enough trailing installer source to exceed shell buffering. Cover existing CLI, uvx/bootstrap, nonzero exits, quoted paths, and terminal/no-terminal behavior.

## Task 3: Integration, docs, and release validation

- Run connect, companions, installer/API, forge, wiki, and service regression suites plus Ruff.
- Update relevant install/forge documentation only where behavior needs clarification.
- Refresh Graphify after code changes.
- Target v0.10.1 through `fix:` commits and the existing Release Please workflow. Do not hand-edit package version, release manifest, or changelog release header. Verify the release configuration would produce a patch release.

## Global constraints

- No database migration, history rewrite, new sync schedule, or additional batching system.
- Scaffold files remain Hub-managed and update when generated content changes.
- Keep the documented one-line installer command unchanged.
- No real network calls or installations in tests.
